## Adversarial review of Stage 5.5 — eleven defects fixed (2026-07-31)

- **D-86 — The same reviewer turned on Stage 5.5 and produced 11 findings. All 11 reproduced; all 11 are fixed. 172 tests pass** (was 164). The reviewer's framing was the right one and worth keeping as a standing check: *the implementation's comments promised stronger behaviour than the code delivered.* Two findings deserve to be named plainly rather than buried in a list:
  - **I reintroduced D-82.** `target_realization` scoped observations by *population* and forgot to scope them by *account*, so an account-wide value target (no segment, no view) read whichever account reported that metric definition most recently. Account A's ledger showed account B's 0.95 as "realized." This is the identical defect I had fixed in the QBR hours earlier and then wrote again in new code. The lesson is not "be careful": metric definitions are global and observations are not, so **any** query joining the two needs an account bound, and that now has a test in both places.
  - **The versioning meant to make re-basing clean is what broke the count.** `active_segments` did not exist; segment reads were `WHERE account_id=?`, which returns every generation of the partition at once. A re-based account reported 1,100 addressable seats against a 1,000-FTE partition — precisely the over-count §1.1 exists to prevent, produced by the feature designed to prevent it. Segment reads in the map, rollup, and next-seats are now scoped to the active partition, and cells belonging to superseded segments are history rather than inventory.
  - **Cross-account whitespace cells (accepted 201).** A cell could claim account A while pointing at account B's segment, aggregating another customer's population into A's rollup. Same look-up-by-id-and-trust-the-caller shape as D-82/D-85; now validated for segment, view, and account-specific use case.
  - **Failed supersede destroyed the bar.** The status flip and the replacement insert were separate transactions, so a replacement that failed its CHECK (accepted with no accepter/date) left the target superseded with nothing superseding it. Now validated first and written in one transaction.
  - **The unallocated remainder bypassed the FTE cap** — a 5,000-person remainder fit inside a 1,000-FTE partition, breaking the reconciliation the remainder exists to make honest. The exemption is removed; the remainder is part of the company.
  - **"Typed links" were untyped in practice.** Cell evidence and ask-calendar work links accepted ids for objects that do not exist (polymorphic columns carry no FK). Now checked against the target table.
  - **The fiscal map was stored and ignored.** Back-scheduling used a generic 80-day offset for the budget step while the operator's recorded `budget_request_deadline` sat unused — the exact "discover it late" failure §4 exists to prevent. The budget step now lands on the client's actual deadline (MM-DD resolved to the latest occurrence on or before the close).
  - **Export dropped headcount provenance.** `source_references` were collected from a fixed table list that predated Stage 5.5, so a headcount observation's citation restored as a dangling id — provenance is the entire point of that record.
  - **Partially accepted: the cohort floor was decoration.** The reviewer showed suppression hid `paid_density` while shipping `paid_seats` and `headcount` in the same payload, so anyone could recompute it. Correct. Rather than suppress more commercial facts, the resolution draws the line where the trust boundary actually is: **metric observations are behavioural data about identifiable people and are now suppressed for sub-floor populations (this was missing entirely — the real hole); seats and headcount are commercial facts about licences and stay visible.** Density suppression is retained but relabelled in code as a display convention — not implying a precise rate over ten people — explicitly *not* a privacy control. This is a net strengthening: security theatre removed, the actual protection added.
  - **Frontend follow-on I caught while fixing:** the new `suppressed` realization status had no entry in `ValueLedger.jsx`'s status map, which would have thrown on `st.glyph` and blanked the tab. Added, plus a `FALLBACK` so a future backend status degrades to "Unknown" instead of a white screen.

## Adversarial review of Stages 1-5 — six defects fixed (2026-07-31)

- **D-85 — An external adversarial review produced 7 reproduction tests against Stages 1-5. Six reproduced and are fixed; one did not and was rejected. 164 tests pass** (was 156). Each repro was re-run against current code rather than taken on trust, and the one false finding was verified by instrumenting the actual return value:
  - **Rejected — "association can mix account and program" does not reproduce.** With stakeholders in two accounts, `association.resolve` returns account A **and** program AP — internally consistent. The test asserted `program_id == bp["id"]` (account B's program), which is not what happens. No change made.
  - **Cross-account onboarding (real).** `seed_onboarding` looked the program up by id and never checked it belonged to the account in the URL, so `POST /accounts/A/onboard` with B's `program_id` seeded A's launch pack onto B's program and wrote checklist rows carrying A's `account_id` against B's `program_id`. Now 422. **This is the same shape as the QBR bug in D-82** — look a row up by id, trust the caller about where it belongs — which is why the fixes are grouped in one test file with that cause named.
  - **Partial write on a bad kickoff date (real).** `_offset()` threw deep inside the milestone loop, after `repo.insert` had already committed the program, so a malformed date returned 500 *and* left an orphan program. The date is now validated before anything is written; 422, nothing persisted.
  - **`fill_placeholder` filled nothing (real, and the most substantive).** Accepting the proposal always INSERTed a new person, leaving the placeholder unidentified: two org-chart rows for one position, and the `unidentified_placeholder` queue trigger firing forever. The proposal payload carries no placeholder reference at all, so the accept path now (a) honours an explicit `placeholder_person_id` override, validated to be a placeholder **in this account**, else (b) auto-matches on role tokens and converts **only when exactly one placeholder matches**, else (c) falls back to creating the person so a newly-named stakeholder is never dropped. The matcher required care: a naive `len > 3` word filter drops "IT" and "HR", which are frequently the only identifying token, while a `len > 1` filter on lowercased text pulls in the pronoun "it" — so uppercase acronyms are extracted case-sensitively *before* lowercasing, and generic ranks (VP, head, director…) are stopped because they appear in every title. Deliberately conservative on ambiguity, per the spec's rule that low-confidence associations are assigned by a human, never guessed.
  - **Accept-then-reject (real).** `reject` never checked current status, so an accepted proposal could be flipped to `rejected` while its created record stayed — an audit trail asserting the operator declined something they accepted. Now 409, pointing at archiving the created object instead.
  - **Duplicate key-date proposals (real, small).** "Go live is 2026-10-01" emitted both a labelled `Go Live` and a second unlabelled `Key date`, because the two dedupe keys differ by label. Bare-date scanning now skips dates that already produced a labelled proposal. Minor, but the 30-second capture rule wins ties and triaging the same fact twice is exactly that cost.
  - **One drain burned two job attempts (real).** `run_pending`'s docstring promises a failed job "is not re-run within the same drain." The `seen` guard was checked *after* `run_next` returned — by which point the handler had already run a second time. The exclusion moved into `_claim_next` as a `NOT IN` on the claim query, so the contract the code documents is now the contract it keeps. Worth noting the class: the invariant was written down and violated, which a test asserting the docstring would have caught at the time.

## Stage 5.5 — whitespace map, value ledger, funding intelligence (2026-07-31)

- **D-84 — Stage 5.5 built (migrations 0017-0019, `app/expansion.py`, `app/routers/expansion.py`, three new Commercial sub-tabs). 156 tests pass** (was 120). Implementation choices worth recording:
  - **The counting rule is enforced in schema and service, not by convention.** `population_segments` (the MECE base partition) is the only additive dimension and the API refuses a segment that would push allocated headcount past the partition's `total_fte` — the map cannot claim 30,000 addressable seats in a 20,000-person company. `population_views` are composites over segments + tags and are returned with `additive: false` and a reason. Row paid seats is the **max** across use cases, never the sum, because use cases are entitlements on a seat: the sum is also returned, labeled as not the answer, so the honest and tempting numbers sit side by side. `rollup` excludes view cells and reports `excluded_view_cells` rather than filtering silently.
  - **Cell state is derived, never stored.** Four facts (`penetration`, `evidence_state`, `blocker_state`, `pursuit_outcome`) with `expansion.derive_state` applying a fixed precedence. There is deliberately **no PATCH path to the four facts** — they move only through `/set-fact`, which requires a reason and writes `cell_state_history` in the same transaction. Gating requires a lane (a gate nobody can act on is not a gate); declining requires a reason and date, enforced by CHECK. Reopen is its own endpoint that clears the outcome while leaving **both** the decline and the reopen in history.
  - **Cohort privacy floor is applied on the way out of the service**, so no caller can route around it: `_suppressed()` returns `{value: None, suppressed: True, reason}` rather than a bare number, and `POST /population-views` refuses to construct a sub-floor composite at all. `min_cohort_size` is a per-account setting (default 25), not a constant — it is a judgment about identifiability that varies, and hard-coding it would make it invisible.
  - **`metric_observations` gained `population_segment_id` / `population_view_id`.** `cohort_label` is free text and cannot be joined to a target, so realization was not computable before this. Nullable and additive: existing observations keep their label and are simply absent from the ledger — a visible gap beats a fuzzy string match attributing the wrong cohort's numbers to a bar.
  - **"Value targets", not "value commitments"** (D-81), versioned via supersede so "we hit the target" means the target agreed *at the time*. Realization is derived at read time with the same freshness rule as the scoreboard: past the threshold it is `unknown`, never a carried-forward good state. `direction` (`at_least` / `at_most`) exists so "response time under 24h" isn't compared backwards.
  - **Value gaps and the map's `penetrated_unevidenced` state are one computation**, surfaced in both places, so the two screens cannot disagree about which cohorts are at risk.
  - **ARR is derived once, in `PATCH /contracts/{id}/revenue`, and stored.** Deriving it per call site is how two screens quietly disagree about revenue. `one_time` yields no ARR rather than a guess, because guessing inflates NRR. Contraction and churn are dated `revenue_events`, not states inferred from a missing row. `revenue_movement` returns absolutes with the base and an `insufficient_data` flag — never a blended rate (§10).
  - **Ask calendars back-schedule on creation** and take lead times from the account's own contract and fiscal map, falling back to defaults with the source labeled (`lead_source`). Steps are typed links to tasks/milestones/compliance items, not a fourth to-do system.
  - **Design-guide amendment landed with the work** rather than gating it (D-83): the heatmap is built from the **existing status palette** because cell states *are* statuses, so the waterfall's "single non-status exception" rule stands unamended. Contrast was measured in-browser, not asserted: the first pass **failed** — neutral glyphs at 3.74:1 and density meta at 4.1:1 — and was fixed by drawing neutral-state glyphs in `--ink-secondary` and stepping the meta line up from `--ink-tertiary`. Audited worst case is now **4.66:1 light / 4.93:1 dark** across every state's label, glyph, and meta.
  - **Stage 0 hygiene closed.** `portfolio_io._INSERT_ORDER` stopped at migration 0005, silently dropping MAP promotion, onboarding, people layers, cadence, ingestion, and all of Stage 5 from a "full" export. Now covers everything through 0019, and **`test_export_covers_every_account_scoped_table` introspects `sqlite_master` and fails when a migration adds an account-scoped table nobody registered** — the only way this stays true. Global search likewise stopped at the v0-v2 object set; `reindex` skips sources whose table is missing, so the staleness was silent. Added comm messages, pull signals, checklist items, whitespace cells, value targets, funding pools, and segments, with a test that would have caught it.
  - Seed: a Terravance grid exercising **all seven derived states**, a partition that reconciles (11,618 allocated + 8,382 unallocated = 20,000 FTE), an 18-person segment that trips the privacy floor, a composite view whose 300 paid seats correctly stay out of the 912 rollup, a reopened decline, two headcount periods so the §3.2 detector has a series, and an ask calendar with a late step. Screenshots in `design-screenshots/stage-5.5/` (both themes).
