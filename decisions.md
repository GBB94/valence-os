## Stage 11.1 — campaign orchestration (2026-08-02)

- **D-101 — Stage 11.1 built (migration 0032, conversion + adjustment + attention). 279 tests pass** (was 266). Choices worth recording:
  - **One nullable column, not a second association table.** §11.1 is explicit: `play_runs` already points at its signal episode, so another join table would model the same relationship twice and give it two places to disagree. `signal_episodes.adoption_campaign_id` plus a partial unique index carries the whole dedupe rule, so a raw INSERT cannot route around it.

## Stage 11 measurement contract — observation comparability (2026-08-01)

- **D-103 — A campaign may only difference two numbers that were the same measurement.** §5.1 names four matching criteria plus a programme rule; `_observation_query` enforced two (definition, population), and its docstring claimed otherwise — "Matches on definition, version, unit and population identity" — which is the sentence that stops a reviewer from checking. Four demonstrated failures, all one root cause: a post reading on **definition version 2** was differenced against a v1 baseline; a **unit change** turned 0.40 `fraction` against 62.0 `percent` into `delta +61.6` and flipped status to `met` against a 0.70 target; **another programme's** reading of the same cohort was used (+0.59, `met`); and a **retracted post observation** silently fell back to an older row, rendering `delta 0.0, not_met` with no caution — so a withdrawn number read as *"the campaign achieved nothing"* rather than *"the evidence was withdrawn"*, and `no_demonstrated_change` is a §5.4 outcome an operator would then record in good faith.

## v0.2 (2026-07-22)

- **D-14 — Closure rules enforced at DB and API layers.** Risk close requires `close_reason` and issue resolve requires `resolution_type` via CHECK constraints (`status='open' OR reason/type NOT NULL`) plus the transition endpoints; mitigation is a separate field that never changes status. Commitments close only through `/close` (records `acknowledged_by`, date, closer, note). Double-close returns 409, not a crash.
- **D-15 — Inbox conversion reuses the exact create path (`execution_ops.create`).** No divergent creation logic; conversion pre-fills `description` from `raw_text`, auto-links `source_interaction_id`, and defaults `program_id` to the source interaction's program. Account-level notes (null program) require choosing a program in the convert form (422 with guidance otherwise).
- **D-16 — Decision supersede is modeled, not deleted.** Creating a decision with `supersedes_id` flips the old one to `superseded` in the same transaction; both are retained (decisions are a log).
- **D-17 — Overdue / at-risk are derived at read time on the board, never stored.** Commitment/task `overdue` = open AND due_date < today; milestone `derived_at_risk` = upcoming AND (at_risk flag OR past target). Keeps status honest without stale stored flags.
